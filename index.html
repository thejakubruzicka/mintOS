Inside

Every layer, built in-house

From the first UEFI call to the last pixel of the dock. Two ways to boot, one kernel, and a desktop that lives in user space and talks to the kernel only through validated system calls.

firmware

UEFI

Loads BOOTX64.EFI from the EFI system partition.

uefi/main.c

Startup selector

Enter, 1 or a 3-second timeout picks UEFI Desktop. 2 or M starts native MintDE.

default · recovery

UEFI Desktop

A firmware-mediated desktop that uses UEFI services for display, input, file volumes and bounded HTTP GET.

ExitBootServices · one way

MintOS26 kernel ring 0

Takes over the machine: its own GDT, IDT, paging, scheduler and drivers.

MintDE ring 3

Reaches the kernel only through the versioned int 0x80 syscall ABI.

kernel/arch/x86_64

CPU bring-up

Own GDT, 64-bit TSS and IDT, with guarded stacks for double faults, NMIs and machine checks.

kernel/mm

Memory

Physical page allocator, NX paging with read-only kernel text, heap, vmalloc and isolated per-process address spaces.

kernel/task

Scheduler

A cooperative scheduler on a PIT timer ticking near 100 Hz.

kernel/proc

Processes

An ELF64 loader for ring-3 programs. A crashing user process is contained instead of taking the kernel down.

kernel/abi

System calls

A versioned syscall ABI where every pointer from user space is validated before the kernel touches it.

kernel/block

Storage

AHCI SATA with LBA48 DMA reads and per-device I/O counters. General writes are blocked by policy.

kernel/fs

Filesystems

A VFS mount table with a RAM-backed /session and up to eight read-only FAT16 volumes under /Volumes.

kernel/bus

PCI

Configuration-space enumeration with BAR and interrupt decoding. Detecting a device is not the same as driving it, and MintOS says so.

kernel/net

Network

An opt-in Intel 82540EM (E1000) driver with bounded DMA rings and a loopback self-test. No TCP/IP yet.

kernel/input

Input

PS/2 keyboard and mouse, with live event counters shown right in Settings.

kernel/ui

Graphics

Framebuffer surfaces, rounded alpha-blended glass panels and RGBA icon drawing for user space.

kernel/console

Diagnostics

Structured COM1 logging, ATA IDENTIFY probes and storage health checks that record exactly what happened.

MintDE

A desktop of its own

MintDE is the native Mint Desktop Environment, versioned separately from the OS. It runs entirely in ring 3 with a glass dock, menus, Launchpad and a set of system apps.

MintDE starts on a clean workspace. The menu bar shows live keyboard and pointer state; everything else lives in the dock and Launchpad.

The bounded diagnostic Terminal running net test in QEMU. The RX timeout is expected there: QEMU's E1000 loops back differently from VirtualBox's, which is the real target.

Status

Honest about where it is

MintOS26 is an experimental hobby OS that runs in virtual machines. Test logs are kept with every release, and nothing is called working until it has been seen working.

Works

  • Boots in QEMU with OVMF firmware, into both UEFI Desktop and native MintDE
  • Startup selector with a safe default and a recovery path
  • Ring-3 desktop with dock, menus, Launchpad, Settings, Files and Terminal
  • PCI enumeration and AHCI SATA disks with LBA48 reads
  • Read-only FAT16, up to eight volumes at once
  • PS/2 keyboard and mouse

In progress

  • E1000 loopback: transmit completes, receive still times out
  • Full MintDE testing in VirtualBox at several screen sizes
  • Window resizing, cursor and menu polish
  • Terminal line editing and process blocking/wake-up

Not yet

  • Saving files to disk (Notes and Settings reset on reboot)
  • TCP/IP, DHCP and DNS
  • USB, NVMe, audio and ACPI power management
  • GPU acceleration
  • Real hardware. VMs only for now

Build

Build it and boot it

Everything is built from source with clang and LLVM's linkers. The build produces the EFI app, kernel, disk images, VirtualBox disks and a bootable ISO.

1

Get the tools

You need clang, lld-link and ld.lld, GNU make and Python 3. On macOS, the Xcode command-line tools plus Homebrew are enough:

brew install lld qemu
2

Build and test

Clone the repository, then build everything and run the host-side checks:

git clone https://github.com/YOUR-GITHUB-USERNAME/MintOS26.git
cd MintOS26
make clean all
make check
3

Boot it in QEMU

Run the UEFI disk with OVMF firmware. At the selector, press 2 or M for native MintDE. The firmware path below is Homebrew's; adjust it on Linux.

qemu-system-x86_64 -machine q35 -m 2G -snapshot \
  -drive if=pflash,format=raw,readonly=on,file=/opt/homebrew/share/qemu/edk2-x86_64-code.fd \
  -drive file=build/mintos26-26.5.008.0-uefi.img,format=raw \
  -drive file=build/mintos26-data-512m.img,format=raw \
  -nic user,model=e1000 -serial stdio
Before you try the native path

MintDE calls ExitBootServices, so the handoff is one way until you reset the VM. Keep EFI enabled and use a snapshot. Disk Utility's blank-disk initializer is destructive, so only point it at a disposable virtual disk, never at real hardware.
